SUAS-015 — SuperUnicode Arabic Mark Rendering

The runtime counterpart of UAX #53: one 12-byte mark-layout record, a parallel combining-class table, and an in-place AMTRA pass the caller can override with a combining grapheme joiner.

SUAS-015 (SUAMR) is the fifteenth SuperUnicode Architecture Standard and the runtime counterpart of UAX #53, Unicode Arabic Mark Rendering. UAX #53 defines the Arabic Mark Transient Reordering Algorithm (AMTRA) in prose and leaves the actual placement of each diacritic to an OpenType shaping engine with dynamically parsed font metrics and runtime heuristics. SUAMR keeps the algorithm and closes the architecture around it: a byte-packed table, a bounded lookup, and a verification surface the compiler must satisfy before it emits a record.

SUAMR does not re-implement SUAS-006 (STS). STS decides where a grapheme cluster begins and ends; SUAMR takes the cluster the caller supplies and reorders its marks. The two compose; neither re-derives the other.

Why a binary property

Aspect UAX #53 / a shaping engine SUAMR
Positioning Glyph placement resolved by GSUB/GPOS at run time A 12-byte static record read from a fixed table
Metrics Font tables parsed at run time Fixed-point offsets compiled at build time
Memory Heap-allocated shaping buffers Zero allocation; the caller owns every buffer

The mark-layout record

Six fields, 12 bytes, no padding on any supported ABI. They are the seeding sketch’s fields, verbatim: codepoint, x_offset, y_offset, positioning_flags, stacking_level and reserved. The offsets are signed fixed-point displacements in 1/64 em.

typedef struct {
uint32_t codepoint; /* Combining mark codepoint */
int16_t x_offset; /* Fixed-point horizontal displacement */
int16_t y_offset; /* Fixed-point vertical displacement */
uint16_t positioning_flags; /* Packed stacking and rendering flags */
uint8_t stacking_level; /* Stacking depth index for multi-mark runs */
uint8_t reserved; /* must be zero */
} suamr_mark_layout_t;

The record carries no combining-class field: the class lives in a parallel table aligned with the layout table at build time. This preserves the sketch’s exact 12 bytes while still carrying the 220/230 generalized classes AMTRA needs.

The positioning flags

Flag Meaning
STACK_ABOVE Stack the mark above the base

The canonical combining classes

UAX #53 Table 1 assigns eleven non-zero ccc values to Arabic script combining marks, plus two generalized classes. SUAMR carries each as a closed constant and, for an uncurated mark, derives the class from its block.

ccc Marks
0 Combining grapheme joiner, combining alef overlay
27–29 Fathatan / dammatan / kasratan and their open forms
30–32 Fatha / damma / kasra and their small forms
33 Shadda
34 Sukun
35 Superscript alef
220 All other below marks except small low noon with kasra
230 All other above marks, small low noon with kasra

The AMTRA transient reordering

AMTRA normalizes the input to NFD, then, within each run of non-starters, reorders the marks into four tiers, front to back: the leading ccc=220 MCM run, the leading ccc=230 MCM run, the shadda (ccc=33), and everything else in its encoded order. suas_suamr_reorder_cluster applies that in place, allocating nothing, and is stable — canonically equivalent sequences render identically.

Input (marks after the base) Output
damma, shadda shadda, damma
fatha, hamza above (MCM) hamza above, fatha
kasra, hamza below (MCM) hamza below, kasra
shadda, fatha, hamza below (MCM) hamza below, shadda, fatha

The combining grapheme joiner (U+034F) pins the mark that follows it: AMTRA never moves a mark across a CGJ. Encode <damma, CGJ, hamza above> to place the hamza above over the damma — the exceptional order, exactly as the orthography demands.

The mistaken U+08D9 assignment

U+08D9 ARABIC SMALL LOW NOON WITH KASRA appears below the text but was mistakenly given ccc=230 in Unicode 9.0, and that cannot now be changed. SUAMR records it as it is — ccc=230, but stacking below — and a conforming implementation gives it no effect on the marks above.

Zones and the total default

A layout query may name only the Bridge plane, the RNUR neography carve-out, or the custom-conscript Native plane. A mark with no curated record is not unknown: suas_suamr_get_mark_layout synthesizes an algorithmic default from the mark’s block and returns true. It returns false only for an inadmissible zone or a NULL output. The property is total.

Zone Range Text space?
BRIDGE 0x00000000–0x0010FFFF Yes
SCP 0x00110000–0x0011FFFF No — Control Plane
NATIVE rest of 0x00120000–0x7FFFFFEF Yes — custom conscript space
RNUR 0x00160000–0x0016FFFF Yes — neography
TRAP / SENTINEL / EXTSUCS terminals and plugin space No

Extension to complex conscript abugidas

Because the stacking engine is fully generalized, the same layout tables extend to complex diacritic stacking in the Native & Neography Plane (0x160000–0x16FFFF) — a conlang writing system such as the Kōpu abvukjelitsā abugida, or a script declared in the Reddit Neographical Unicode Registry (RNUR), carries CUSTOM_CLASS so a renderer knows the positioning came from a registry declaration rather than a historical default.

Verification names the defect

suas_suamr_validate_table returns the first of twelve named outcomes: a NULL table, a count over capacity, an unordered pair, a duplicate codepoint, a codepoint past the space, an inadmissible codepoint, an invalid combining class, a reserved or contradictory flag bit, both stacking sides set at once, a nonzero reserved byte, or a custom-class claim outside the RNUR set. An empty registry is valid: an implementation with no curated records ships zero rows and conforms.

Classification note

SUAMR is a SUAS core invariant, registered as SUAS-015, the number immediately after SUAS-014 (SUVTL). One element of the SUTS framing survives deliberately: the registry contents are optional version data, so an implementation with no curated records ships an empty table and remains conformant — while the engine, the record layout, the reordering rules and the verification rules are mandatory architecture.

The seeding sketch named its offline layer “SUCA”. In this corpus SUCA is already the SuperUnicode Collation Algorithm (SUTS-001), so SUAMR names SUCD (SUAS-012) as its reference layer — exactly as SIP, SCSS, SISR and SUVTL already do.

Reference implementation: include/suas/suas_suamr.h + src/suas/suas_suamr.c (freestanding C99, no heap), registered in suas_static and in the SSRE registry as a MANDATORY specification.
