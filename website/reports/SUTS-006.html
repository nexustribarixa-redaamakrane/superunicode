SUTS-006 — Internationalized Domain & Identifier Network

The sixth SuperUnicode Technical Specification: a single-pass, zero-allocation engine for mapping, validating, and canonically routing internationalized labels in the OpenWindows microkernel.

SUTS-006 (SIDN) is the sixth SuperUnicode Technical Specification and a core kernel primitive of the OpenWindows microkernel. It establishes a binary-compiled, zero-allocation architecture for internationalized domain and identifier routing — mapping a codepoint to a compiled IDNA Status, validating a whole label in a single pass, and producing a canonical binary routing form — replacing the text-based pipeline of Unicode’s UTS #46 (IdnaMappingTable.txt, Map → NFC → Punycode → Validate) with fixed-size, byte-aligned memory layouts optimized for O(1) kernel execution.

Why not a text IDNA pipeline

  • Single pass vs. text pipeline — UTS #46 runs Map → Normalize (NFC) → Break → Convert → Validate over dynamically allocated strings; SIDN walks the label once, applies each codepoint’s compiled Status as it goes, and emits the canonical form in the same pass.
  • Direct 31-bit routing vs. Punycode — UTS #46 ToASCII produces an ASCII xn-- encoding for the DNS wire; a SuperUnicode network carries SUCS codepoints directly, so SIDN never performs an ASCII encoding loop at all.
  • Zero allocation vs. heap — a user-space IDNA layer buffers every pipeline stage and loads the mapping table into heap-resident maps; SIDN resolves from one static table and one fixed index, materializing a label into a bounded stack buffer.
  • Kernel primitive vs. user-space — UTS #46 targets browsers, registrars, and library authors reading files from disk; SIDN gives the microkernel, the shell parser, the IPC namespace, and the routing table deterministic, in-band verdicts.

Dual-layer architecture

Layer Role
SUCD — offline reference Full text manifests: the IDNA mapping table, label restriction rules, and domain-profile definitions for network compilers and user-space applications
SIDN — runtime kernel Immutable, byte-packed binary routing tables (sidn_mapping_entry_t, sidn_label_descriptor_t) queried by the kernel in O(1)

Build-time tooling distils the SUCD IDNA datasets into the tables the kernel embeds. The seeding sketch labelled SIDN “SUAS-015” and named its offline layer “SUCD — SUAS-014”; both numbers were stale. In this corpus SUCD is the SuperUnicode Character Database (SUAS-012), SISR is SUAS-013, and SIDN is registered as SUTS-006 — the number freed when SISR moved from SUTS-006 to the SUAS series.

Address-space model

SIDN does not invent a second plane taxonomy: suts_sidn_zone_of classifies a codepoint into the SUCD / SSP planes with the RNUR carve-out made explicit. Only the Bridge (0x00000000–0x0010FFFF), the RNUR neography zone (0x00160000–0x0016FFFF), and the Native plane are routable; the Control Plane, the trap slots, the Sentinel, and ExtSUCS are never label material.

Compiled mapping metadata

A mapping record is a compiled 16-byte entry binding a codepoint to its Status and mapping value; the sketch’s label descriptor is preserved unchanged at 8 bytes. Codepoints are 31-bit SUCS values, so an RNUR neography codepoint in 0x00160000–0x0016FFFF and an ExtSUCS plugin codepoint above 0x7FFFFFFF are classified correctly.

#define SIDN_MAPPING_CAPACITY 128U
#define SIDN_MAPPING_INDEX_SIZE 256U
#define SIDN_LABEL_MAX_DNS 63U
#define SIDN_DOMAIN_MAX_DNS 253U

#define SIDN_FLAG_VALID_LABEL (1U << 0)
#define SIDN_FLAG_TRANSITIONAL (1U << 1)
#define SIDN_FLAG_DISALLOWED (1U << 2)
#define SIDN_FLAG_NEOGRAPHY_DOMAIN (1U << 3)

typedef struct {
uint32_t codepoint; /* base SUCS codepoint */
uint32_t mapping[2]; /* replacement, up to two */
uint8_t status; /* sidn_status_t */
uint8_t mapping_length; /* 0, 1 or 2 */
uint16_t reserved; /* must be zero */
} sidn_mapping_entry_t;

typedef struct {
uint32_t label_hash; /* hash of the normalized stream */
uint16_t length; /* codepoint count */
uint16_t flags; /* SIDN_FLAG_* */
} sidn_label_descriptor_t;

Mapping status and deviations

Every codepoint resolves to one of five compiled Status values — valid, ignored, mapped, deviation, disallowed — as a fixed-size record, not by tokenizing a semicolon-delimited data line. Four codepoints are deviations: U+00DF (ß), U+03C2 (ς), U+200C (ZWNJ), and U+200D (ZWJ). Nontransitional processing is the default: a deviation is kept, and the transitional UTS #46 C1 behavior is deprecated.

Label separators and canonical routing

The four label separators — U+002E, U+FF0E, U+3002, and U+FF61 — all fold to U+002E, ending the label. suts_sidn_to_canonical resolves a network label to its canonical binary routing form: the mapped, single-label SUCS stream. Two labels are routing-equivalent exactly when their canonical forms are codepoint-identical, so BÜCHER, bücher, and a fullwidth-capital form all resolve to U+0062 U+00FC U+0063 U+0068 U+0065 U+0072 and reach the same endpoint.

Validity criteria

  • Hyphen position — no leading or trailing hyphen, and no hyphen in both the third and fourth positions.
  • Reserved prefix — the label does not begin with the three codepoints x n -, reserved for the deprecated ACE encoding.
  • STD3 ASCII — every ASCII codepoint is [a-z0-9-]; non-ASCII codepoints are unconstrained.
  • ContextJ — every U+200C or U+200D is in an admissible context (Arabic or Devanagari virama).
  • Bidi — a label containing an RTL letter does not begin with a combining mark, and a mixed RTL/LTR label ends in an RTL letter.
  • DNS length — at most 63 codepoints per label; 253 per name.

Security integration with SCSS

SIDN and SUTS-005 (SCSS) divide the network-naming problem. SIDN answers is this name well-formed and does it name one endpoint; SCSS answers does this name impersonate another. They compose on the routing path: validate and canonicalize with SIDN, screen the canonical form for homographs and script mixing with SCSS, and admit the name only when both agree.
