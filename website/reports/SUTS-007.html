SUTS-007 — SuperUnicode Emoji & Presentation

The seventh SuperUnicode Technical Specification: a zero-allocation, O(1) engine for emoji presentation and flattened ZWJ / modifier sequence resolution in the OpenWindows microkernel.

SUTS-007 (SUEPS) is the seventh SuperUnicode Technical Specification and a core kernel primitive of the OpenWindows microkernel. It establishes a binary-compiled, zero-allocation architecture for emoji presentation — resolving a codepoint to its presentation flags and a base + modifier pair to a precompiled sequence token — replacing the text-based pipeline of Unicode’s UTS #51 (emoji-data.txt, emoji-test.txt, a ZWJ sequence scanner) with fixed-size, byte-aligned memory layouts optimized for O(1) kernel execution.

Why not a text emoji library

  • Atomic scalars vs. surrogate pairs — in UTF-16 an emoji above the BMP is a surrogate pair (😀 is U+1F600, encoded \uD83D\uDE00) that every consumer must recombine; SuperUnicode has no surrogate mechanism at all, so U+1F600 is one atomic 31-bit scalar and there is nothing to recombine.
  • Flattened table vs. string parser — UTS #51 leaves a modifier sequence, a ZWJ sequence, a flag pair, a keycap sequence, and a tag sequence to a sequence-aware scanner; SUEPS flattens every admitted chain into static binary transition tables resolved by one hash and one bounded probe.
  • Zero allocation vs. heap maps — a user-space emoji layer loads the annotation set into heap-resident hash maps and buffers each sequence stage; SUEPS resolves every property from one static table and one fixed index, holding no per-query state.
  • Kernel primitive vs. user-space — UTS #51 targets chat and email applications reading data files from disk; SUEPS gives the graphical subsystem, the text-rendering path, and the emoji palette deterministic, in-band verdicts.

The “No Surrogates” mandate

SUEPS inherits the second non-negotiable invariant of the SuperUnicode transformation formats, SUTR-1 (SUTF) §1.2: SuperUnicode has no surrogate mechanism. The range U+D800–U+DFFF is an ordinary block of valid PUA codepoints and MUST be encoded as such — never paired, never reserved, never rejected. A Unicode emoji above the BMP is one surrogate pair in UTF-16 and every consumer must recombine it; SUEPS has no such step, because there is no such pair. U+D83D alone is not a broken half — it is an ordinary valid PUA codepoint, and suts_sueps_is_pua_half classifies that block rather than rejecting it.

UTF-16 (UTS #51) SuperUnicode (SUEPS)
😀 U+1F600 two code units D83D DE00, recombined one atomic 31-bit scalar 0x0001F600
U+D83D alone an unpaired surrogate: ill-formed an ordinary valid PUA codepoint
U+DC00 alone an unpaired surrogate: ill-formed an ordinary valid PUA codepoint

Dual-layer architecture

Layer Role
SUCD — offline reference Full human-readable emoji annotation files, sequence charts, and presentation property manifests for user-space applications, font designers, and toolchains
SUEPS — runtime kernel Immutable, byte-packed binary lookup tables (sueps_emoji_entry_t, the flattened modifier transition table) queried by the kernel in O(1)

As with SIP, SSRE, SUCD, and SIDN, the brief named the offline layer “SUCA”; in this corpus SUCA is already the SuperUnicode Collation Algorithm (SUTS-001), so SUEPS names SUCD (SUAS-012) as its reference layer. The house prefix SUEPS_* and the entry points suts_sueps_init_registry, suts_sueps_get_entry, and suts_sueps_resolve_sequence are preserved verbatim.

Address-space model

SUEPS does not invent a second plane taxonomy: suts_sueps_zone_of classifies a codepoint into the SUCD / SSP planes with the RNUR carve-out made explicit. Only the Bridge (0x00000000–0x0010FFFF), the RNUR neography zone (0x00160000–0x0016FFFF), and the Native plane are emoji material; the Control Plane, the trap slots, the Sentinel, and ExtSUCS are never emoji material. The former-surrogate block sits squarely inside the Bridge zone: it is renderable, because SUTR-1 makes it ordinary PUA.

Compiled emoji metadata

A compiled emoji record is a fixed 12-byte entry binding a 31-bit codepoint to its packed presentation flags, a precomputed sequence-token hash, and a modifier-base reference; the sketch’s field layout is preserved unchanged. Codepoints are 31-bit SUCS values, so an RNUR neography emoji in 0x00160000–0x0016FFFF is classified correctly and an ExtSUCS plugin codepoint above 0x7FFFFFFF is refused.

#define SUEPS_ENTRY_CAPACITY 128U
#define SUEPS_ENTRY_INDEX_SIZE 256U

#define SUEPS_FLAG_EMOJI (1U << 0)
#define SUEPS_FLAG_TEXT_DEFAULT (1U << 1)
#define SUEPS_FLAG_MODIFIER (1U << 2)
#define SUEPS_FLAG_ZWJ_SEQUENCE (1U << 3)

typedef struct {
uint32_t codepoint; /* Direct 31-bit codepoint (No Surrogates) */
uint32_t sequence_hash; /* Precomputed token hash for chains */
uint16_t presentation_flags; /* Packed attribute flags */
uint8_t modifier_base; /* Associated base character reference */
uint8_t reserved; /* must be zero */
} sueps_emoji_entry_t; /* exactly 12 bytes */

Presentation class and sequence resolution

A curated emoji records whether it is default emoji presentation (ED-6) or default text presentation (ED-7); U+FE0E (VS15) requests a text presentation and U+FE0F (VS16) an emoji presentation, and both are components, never emoji alone. A base + modifier pair resolves through the flattened transition table: suts_sueps_resolve_sequence(0x1F44D, 0x1F3FD) returns the base record with SUEPS_FLAG_MODIFIER and SUEPS_FLAG_ZWJ_SEQUENCE set and sequence_hash set to the precomputed pair token — no re-scan and no dynamic buffer.

Resolution codes

Code Meaning
SUEPS_ERR_NULL_ARGUMENT a NULL output descriptor
SUEPS_ERR_NOT_EMOJI the base carries no emoji record
SUEPS_ERR_BAD_BASE the base is not an emoji modifier base (ED-12)
SUEPS_ERR_BAD_MODIFIER the second codepoint is not an emoji modifier (ED-11)
SUEPS_ERR_ILLEGAL_ZONE a Control Plane / trap / Sentinel / ExtSUCS argument
SUEPS_ERR_UNQUALIFIED the pair is not a qualified sequence

Modular optional compliance

SUEPS is a modular specification. The architectural contract — the record layout, the lookup, the flattened transition table, the “No Surrogates” rule — is mandatory for an implementation that claims SUEPS support; but a lightweight server kernel or a headless environment MAY omit the module entirely, because core primitives, file paths, and kernel IPC channels require strict text safety rather than graphical emoticons.
