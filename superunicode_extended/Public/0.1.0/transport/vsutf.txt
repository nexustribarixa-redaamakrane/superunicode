# vsutf.txt - vSUTF (Variable SUTF) Transformation Format
#
# Three regimes, not a uniform variable-length integer:
#
#   0x00000000 - 0x7FFFFFFF    standard SUTF-8 framing, 1-6 bytes
#   0x80000000 - 0xFFFFFFFFFFFFFFFF
#                              0xFE prefix + 8 bytes big-endian = 9 bytes
#   > 0xFFFFFFFFFFFFFFFF       0xFF prefix
#                              + unsigned LEB128 payload byte count L
#                              + L bytes big-endian (no leading zero)
#
# The 0xFF regime is the arbitrary-precision regime. L is canonical (minimal
# LEB128) and MUST be at least 9. There is NO maximum L and therefore NO
# maximum ExtSUCS codepoint. The value is limited only by caller storage and
# the platform's addressable memory, never by the format.
#
# 0xFE and 0xFF are unused as SUTF-8 lead bytes (which are 0xC0-0xFD), so
# they are safe extension markers. A LEB128-style variable-length integer
# could NOT coexist with SUTF-8 lead bytes, because those two values would
# be ambiguous.
#
# The Base regime is byte-for-byte SUTF-8, so any Base SUCS stream is
# already a valid vSUTF stream. VSUTF_MAX_BYTES (9) is the maximum only for
# the 64-bit fast path; arbitrary-precision codepoints have no fixed maximum.
# A codepoint in the inherited trap range returns length 0 and is not
# encodable.
#
# See vsutf.h for the normative reference implementation.
