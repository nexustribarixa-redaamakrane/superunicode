SUTS-004 — System Ideographic Variation Database

The fourth SuperUnicode Technical Specification: binary-compiled variant sequences for the OpenWindows microkernel and its suf font pipeline.

SUTS-004 (SIVD) is the fourth SuperUnicode Technical Specification and a core kernel primitive of the OpenWindows microkernel. It establishes a binary-compiled, zero-allocation schema for ideographic and stylistic character variant sequences — mapping a registered variation sequence (a base ideograph followed by a variation selector) to a specific glyph — that bypasses the text-heavy, multi-megabyte flat files of Unicode’s UTS #37 Ideographic Variation Database in favour of fixed-size, byte-aligned layouts optimized for O(1) kernel execution and font-pipeline lookup.

Why not a flat-file IVD

  • Compiled binary vs. text registries — UTS #37 is two UTF-8 files (IVD_Collections.txt, IVD_Sequences.txt) tokenized at run time; SIVD is fixed-size C structs in read-only memory, at known offsets, with no parser.
  • Zero allocation vs. heap — a user-space IVD loads the registries into dynamic maps and tables; SIVD resolves from a static table and a fixed index, never touching a heap.
  • Kernel primitive vs. user-space — the IVD targets layout engines reading files from disk; SIVD gives the microkernel, the suf font pipeline, and the terminal drivers deterministic variant resolution in-band.

The dual-plane variation index

Plane Range Contents
Bridge Variation Space 0x000000–0x10FFFF Standard Ideographic Variation Sequences over the supplementary selectors U+E0100–U+E01EF
Native & Neography 0x160000–0x16FFFF RNUR neography scripts and conlangs: contextual alternates, regional forms, stylistic flourishes

Binary variation schema

#define SUTS_SIVD_MAX_COLLECTION_ID 32U
#define SUTS_SIVD_MAX_ENTRY_ID 16U
#define SUTS_SIVD_MAX_ID_PATTERN 32U
#define SUTS_SIVD_REGISTRY_CAPACITY 128U
#define SUTS_SIVD_COLLECTION_CAPACITY 16U
#define SUTS_SIVD_INDEX_SIZE 256U

typedef struct {
sucs_ex_char_t base_codepoint;
sucs_ex_char_t variation_selector;
uint32_t resolved_glyph_index;
uint16_t collection_index;
uint8_t plane;
uint8_t flags;
} sivd_variation_entry_t;

Codepoints are sucs_ex_char_t (64-bit), not uint32_t, so an RNUR neography base in 0x00160000–0x0016FFFF and an ExtSUCS plugin base above 0x7FFFFFFF survive intact. resolved_glyph_index is the font-bundle-relative uint32_t glyph_id the suf vector font engine renders.

Collections

Registered sequences are grouped into collections, each owning a contiguous run of entries so enumeration is an O(1) range walk. The identifier pattern is stored as an opaque descriptor: SIVD never evaluates it, because there is no regex engine on the lookup path. The reference table holds 20 entries in 6 collections, including the Annex B example <82A6 E0134>.

Zero-allocation resolution

Operation Cost
sivd_resolve_variant O(1) expected (bounded probes), no allocation
sivd_init_registry O(n) once, n ≤ 128, no allocation
sivd_lookup / is_registered / collection_of O(1) expected
sivd_entry_at / collection_at / plane_of O(1)

Font pipeline integration (suf)

The layout pass emits codepoints one at a time. When it reads a valid base followed by a variation selector it forms the pair, calls sivd_resolve_variant for the glyph index in O(1), and feeds that index to the suf outline and metric lookup. On a miss the selector is default-ignorable and the base renders its default glyph. The path is single-pass and allocation-free: one probe per selector, a fixed stack, no character-map rebuild.
