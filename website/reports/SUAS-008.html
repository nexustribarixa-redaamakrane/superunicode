SUAS-008 — System Named Character Sequences

The eighth SuperUnicode Architecture Standard: a zero-allocation, static-registry, O(1) resolver for multi-codepoint symbol names (a UAX #34 analog).

SUAS-008 (SNCS) is the eighth SuperUnicode Architecture Standard. It gives a name to a sequence of codepoints, so that a symbol which is not a single codepoint — a combining cluster, a ligature, a flag emoji, or a neography logograph — can be referred to, looked up, and rendered by one stable token. Where UAX #34 defines named character sequences through dynamic string tables, SNCS binds the concept to a zero-allocation, static lookup table optimized for the OpenWindows shell and the SUF font engine. A name resolves to its packed codepoint token in O(1), with no heap, no dynamic table growth, and no string parsing.

Dual-registry index

Registry Range Purpose
SUAS_SNCS_REGISTRY_BRIDGE 0x000000–0x10FFFF Standard compatibility sequences mapped from the Unicode named sequence registry
SUAS_SNCS_REGISTRY_NATIVE 0x160000–0x16FFFF RNUR neography compound glyphs, ligatures, and multi-codepoint logographs

RCCR functions separately as an out-of-band metadata/subtag registry for language identification and allocates no codepoints; it therefore contributes no SNCS sequences. A sequence is classified as Native iff any of its codepoints lies in the Native plane.

The static token

A resolved sequence is a fixed-size, stack-allocatable token. Codepoints are 64-bit (sucs_ex_char_t), so one token spans the Unicode Bridge, the System Control Plane, the Native plane, and the unbounded extSUCS plugin space uniformly. A named character sequence is always two or more codepoints. The name limit was raised from the seeding sketch’s 32 bytes to 64, because 32 truncates most Unicode named-sequence names.

#define SUAS_SNCS_MAX_SEQUENCE_LEN 8U
#define SUAS_SNCS_MAX_NAME_LEN 64U

typedef struct {
char name[SUAS_SNCS_MAX_NAME_LEN];
sucs_ex_char_t codepoints[SUAS_SNCS_MAX_SEQUENCE_LEN];
uint8_t length;
} suas_named_sequence_t;

Name rules

Rule Subject
SNCS-R1 Only A–Z, digits 0–9 (not first in a word), SPACE, and HYPHEN-MINUS
SNCS-R2 One name per sequence; unique within the SUCS namespace for names
SNCS-R3 Unique even ignoring SPACE, medial HYPHEN-MINUS, and LETTER / CHARACTER / DIGIT

Resolution

The registry is a static array of at most SUAS_SNCS_REGISTRY_CAPACITY (64) tokens, indexed once into a fixed array of SUAS_SNCS_INDEX_SIZE (128) open-addressing slots (FNV-1a hash, linear probing). Resolution hashes the query name and probes a bounded number of slots. The index is built lazily on first use and is idempotent; it never grows at run time.

Operation Cost
suas_sncs_resolve_sequence O(1) expected (bounded probes), no allocation
suas_sncs_init_registry O(n) once, n ≤ 64, no allocation
suas_sncs_sequence_at / registry_count O(1)
suas_sncs_registry_of O(length), length ≤ 8
Feature Status
Static multi-codepoint packing Yes
O(1) name resolution, no heap Yes
Dual registry: Bridge + RNUR neography Yes
SCP / trap / Sentinel invariance Yes
SNCS-R1 validity and SNCS-R3 uniqueness Yes
Lazy, idempotent index build Yes
Freestanding C99 Yes
