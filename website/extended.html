SuperUnicode Extended

ExtSUCS — codepoint territory without a ceiling, added by plugins.

Base SUCS ends at the Sentinel value 0x7FFFFFFF — the default runtime ceiling on websites and ordinary devices. SuperUnicode Extended (ExtSUCS) removes the ceiling: its codepoints are held in a 64-bit sucs_ex_char_t, and new codepoints are contributed by plugins.

How a plugin works

A plugin is a self-contained package of codepoints: it declares ranges (all strictly above 0x7FFFFFFF), a name table, properties, mappings and optional collation. Installing one is a two-phase operation, exactly like a mode switch:

  1. Stage. The plugin blob is written to the staging table. The kernel answers SUCS_PLUGIN_REBOOT_REQUIRED — a restart is mandatory.
  2. Commit on boot. At early boot the kernel runs the checksum gate: the blob's CRC32c and Fletcher-64 must match. A valid plugin mounts as a SuperUnicode Plugin Partition and its ranges register into ExtSUCS.
  3. Quarantine. A blob that fails any gate is never mounted and never registers. It is quarantined and dispatched through the trap/BANcode machinery.
stage install -> SUCS_PLUGIN_REBOOT_REQUIRED
boot -> crc32c + fletcher64 verify
-> mount SuperUnicode Plugin Partition (OWFS, read-only)
-> register ranges into ExtSUCS
gate failed -> quarantine — never mounted

The registry

Approved plugins are recorded in extsucd/registry.txt inside the Extended /Public tree, and their full packages live under extsucd/plugins/<plugin-id>/. The 0.1.0 registry opens with the demonstration plugin org.openwindows.hellocp:

org.openwindows.hellocp | 1.0.0 | 1 @ 0x80000000-0x80000FFF | OWFS | approved

The plugin SDK

Plugin authors build against the loader ABI (plugin.h). The SDK ships a copy-this template, a full worked example, and offline tooling:

Template

plugin_entry.c with the one required export, sucs_plugin_entry(), plus data/mapping/collation modules.

hellocp example

A complete, packable plugin that declares 4096 codepoints at 0x80000000.

plugin_pack / plugin_verify

Assemble a plugin blob and verify its checksum gate offline — exactly what the boot loader will do.

Download

The whole SDK ships as Plugin-SDK.zip in the Extended /Public tree.

Transport

Because plugin codepoints exceed 31 bits, Extended defines its own transport families over sucs_ex_char_t:

  • Vector — length-prefixed sequences of 64-bit codepoints.
  • vsutf — variable-length integer framing that covers the full 64-bit space.
  • esutf — the fixed-base Extended SUTF family, complementing the Base SUTF8/16/32 which cap at 0x7FFFFFFF.

Base and Extended are one system. ExtSUCS inherits the SCP, traps and Sentinel from Base SUCS verbatim. Base partitions may be OWFS or USFS; plugin partitions are always OWFS, always read-only, always checksum-gated. Back to the Base standard »
