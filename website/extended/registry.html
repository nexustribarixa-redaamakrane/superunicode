The registry

Recorded plugins, their ranges and their recorded state.

The ExtSUCS registry is extsucd/registry.txt in the Extended /Public tree. Each row records a plugin id, version, ranges, partition format and the state string recorded by the registry. Full packages live under extsucd/plugins/<plugin-id>/.

The registry records which ranges are claimed by a plugin. It does not by itself grant authority: a plugin becomes authoritative for its ranges only after it mounts and registers, as described below.

Plugin id Version Ranges Format State
org.openwindows.hellocp 1.0.0 0x80000000–0x80000FFF OWFS approved

The state value is reproduced from registry.txt; in the 0.1.0 data the single entry is recorded as approved. The data tree defines a mechanical rule — a plugin is recorded as approved when its package is under plugins/<id>/ and a row is added to registry.txt — but it documents no formal review, committee, or external approval process.

Registry rules

  • Every plugin range lies in the Native plane (0x120000–0x7FFFFFEF) or strictly above 0x7FFFFFFF.
  • Ranges may not overlap another plugin’s ranges — collisions are rejected both offline (plugin_verify) and at boot.
  • A plugin becomes authoritative for its ranges only after it mounts and registers.
  • Registry rows mirror the plugin manifest; the checksums in security/ attest each published blob.

In the database: extsucd/registry.txt and extsucd/plugins/org.openwindows.hellocp/.
