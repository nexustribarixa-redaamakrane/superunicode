SUAS-009 — System Ideographic Properties

The ninth SuperUnicode Architecture Standard: a zero-allocation, O(1) engine for ideographic radical-stroke, classification, and variant data (a UAX #38 analog).

SUAS-009 (SIP) is the ninth SuperUnicode Architecture Standard. It governs the zero-allocation, O(1) querying and bitfield extraction of ideographic character attributes: the Kangxi radical, the stroke count, a classification bitfield, a collation seed, and the linkage to a regional or historical variant. Where a traditional Unicode environment consults the multi-megabyte Unihan Database (UAX #38) — full of historical notes and string properties parsed at run time — SIP compiles the same concept into immutable, byte-packed binary tables that the kernel reads directly, with no text parsing and no heap.

Dual-layer architecture

Layer Role
SUCD — offline reference Full text manifests and flat-file datasets for developer tooling, user-space applications, and offline documentation
SIP — runtime kernel Immutable, byte-packed binary tables (suas_glyph_prop_t) queried by the kernel in O(1)

The seeding brief named the offline layer “SUCA”; in this corpus SUCA is already the SuperUnicode Collation Algorithm (SUTS-001), so SIP names SUCD (the SuperUnicode Character Database) as its reference layer.

The static record

A queried property set is a fixed-size, stack-allocatable record. The seeding sketch’s five core fields are kept verbatim and in order; codepoint is widened to 64-bit sucs_ex_char_t so an RNUR neography logograph survives, and one additive field, native_variant, carries the variant linkage. The record is 24 bytes on both 32- and 64-bit ABIs.

typedef struct {
sucs_ex_char_t codepoint; /* e.g. U+4E00 */
uint16_t radical; /* Kangxi radical (0 = none) */
uint8_t strokes; /* total stroke count */
uint8_t flags; /* SUAS_SIP_FLAG_* */
uint32_t sort_weight; /* SUCA collation seed */
sucs_ex_char_t native_variant; /* Native/RNUR target, or 0 */
} suas_glyph_prop_t;

Property extraction

SIP discards the human-readable text keys in favour of direct bitfield masking and a hash-indexed static array. The text-only properties stay in the offline SUCD layer and never reach the kernel path.

UAX #38 key SIP representation
kRSUnicode / kTotalStrokes radical + strokes
kPrimaryNumeric SUAS_SIP_FLAG_NUMERIC
kCompatibilityVariant SUAS_SIP_FLAG_COMPAT + sort-weight fold
kSimplifiedVariant / kTraditionalVariant SUAS_SIP_FLAG_TRADITIONAL / native_variant
kMandarin, kDefinition, kIRG_* Not carried — offline SUCD only

Classification flags

Flag Meaning
SUAS_SIP_FLAG_UNIFIED Unified_Ideograph
SUAS_SIP_FLAG_RADICAL Radical-stroke data present
SUAS_SIP_FLAG_VARIANT Carries a variant linkage
SUAS_SIP_FLAG_NUMERIC Carries a numeric value
SUAS_SIP_FLAG_NATIVE Native / RNUR-plane logograph
SUAS_SIP_FLAG_COMPAT Compatibility ideograph
SUAS_SIP_FLAG_TRADITIONAL Traditional (vs. simplified) form

Variant routing and the repertoire

For an ideograph that needs a distinct regional or historical representation beyond Unicode Han unification, suas_sip_variant_target routes the query directly into the Native & Neography Plane (0x160000–0x16FFFF) and the SIVD variation database (SUTS-004). suas_sip_is_ideograph decides repertoire membership by O(1) range dispatch, so an unregistered but valid ideograph is still recognized; compatibility forms fold their sort weight onto their canonical unified counterpart.

Resolution

The table is a static array of at most SUAS_SIP_REGISTRY_CAPACITY (128) records, indexed once into a fixed array of SUAS_SIP_INDEX_SIZE (256) open-addressing slots (FNV-1a hash, linear probing). Every query hashes the codepoint and probes a bounded number of slots. The index is built lazily on first use and is idempotent; it never grows at run time.

Operation Cost
suas_sip_get_properties O(1) expected (bounded probes), no allocation

suas_sip_is_ideograph O(1) range dispatch
suas_sip_get_sort_weight O(1) stored, or algorithmic native-order fallback
