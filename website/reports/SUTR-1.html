SUTR-1 — SUTF

The SuperUnicode Character Encoding Forms: SUTF-8, SUTF-16, SUTF-4, SUTF-2 and vSUTF.

SUTF is Level 3 of the SUCEM model: a character encoding form maps the 31-bit SUCS_CP values of the coded character set to sequences of code units. A code unit is an integer of a specified binary width. All SUTF forms are lossless over the full Base space, and every one of them is endian-neutral — none of them states a byte order.

Form Code unit Covers Shape
SUTF-8 byte Full 31-bit space Variable, 1–6 bytes. Standard UTF-8 parity to 0x10FFFF, extending to 6 bytes for the native extended planes, per sutf8.h.
SUTF-16 16-bit word Full 31-bit space Variable, 1–2 words: one to 0x7FFF, two above. No surrogates — 0xD800–0xDFFF are valid PUA codepoints.
SUTF-4 4-bit nibble Full 31-bit space A fixed count of hex nibbles; for console and bus debugging.
SUTF-2 2-bit frame Full 31-bit space Symbol-frame transformation for narrow IPC channels.
vSUTF byte Full 64-bit ExtSUCS space Variable-length streaming form with a Base-SUCS fast path, per vsutf.h.

What SUTF deliberately does not decide

Because a CEF is a transformation and not a serialization, SUTF says nothing about byte order, memory layout, register alignment or frame structure. That is Level 4, and it lives in the SUST family.

  • SUTF-16 needs an explicit order decision to become a byte stream. SUST-16 makes it: the canonical big-endian serialization of the SUTF-16 word stream. There is no “SUTF-16-LE” — little-endian is a different CES, not a different CEF.
  • Fixed-width 32-bit, 64-bit, 128-bit, 256-bit, 512-bit and arbitrary N-word framings are likewise SUST-32/64/128/256/512/N, defined in sustfixed.h. A fixed 32-bit form is therefore not an SUTF form, and neither is it little-endian by default.
  • SUTF-8 is byte-oriented, so its CES is the identity and no SUST-8 exists.

The operative test: if the processor byte order changed, would this format change? No → SUTF. Yes → SUST. See SUTR-7 for why the two are separate modules.
